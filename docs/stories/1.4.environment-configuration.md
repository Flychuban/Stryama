# Story 1.4: Environment Configuration and Security

## Status
Draft

## Story
**As a** developer,
**I want** environment variable management and security configurations,
**so that** sensitive data is protected and deployment environments are properly configured.

## Acceptance Criteria
1. Create `.env.example` with all required environment variables documented
2. Set up `.env.local` for development with placeholder values
3. Configure environment variable validation using Zod schemas in `env.mjs`
4. Add security headers in `next.config.js` (CSP, HSTS, X-Frame-Options)
5. Set up CORS configuration for API routes with proper origin restrictions
6. Configure runtime environment validation that fails fast on missing variables
7. Document environment setup process in README.md

### Required Environment Variables
```bash
# Database
DATABASE_URL=postgresql://...

# Clerk Authentication
CLERK_SECRET_KEY=sk_test_...
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_...
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up

# AI Services
ANTHROPIC_API_KEY=sk-ant-...

# Sandbox
E2B_API_KEY=e2b_...

# App
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

### Environment Validation Pattern (env.mjs)
```typescript
import { z } from "zod";

const server = z.object({
  DATABASE_URL: z.string().url(),
  CLERK_SECRET_KEY: z.string().min(1),
  ANTHROPIC_API_KEY: z.string().startsWith("sk-ant-"),
  E2B_API_KEY: z.string().startsWith("e2b_"),
});

const client = z.object({
  NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY: z.string().min(1),
  NEXT_PUBLIC_APP_URL: z.string().url(),
});

export const env = {
  server: server.parse(process.env),
  client: client.parse({
    NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY: process.env.NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY,
    NEXT_PUBLIC_APP_URL: process.env.NEXT_PUBLIC_APP_URL,
  }),
};
```

### Security Headers Configuration
```javascript
// next.config.js
const securityHeaders = [
  {
    key: 'X-Frame-Options',
    value: 'SAMEORIGIN'
  },
  {
    key: 'X-Content-Type-Options',
    value: 'nosniff'
  },
  {
    key: 'Referrer-Policy',
    value: 'strict-origin-when-cross-origin'
  },
  {
    key: 'Strict-Transport-Security',
    value: 'max-age=31536000; includeSubDomains'
  }
];
```

### Testing
#### Testing Standards
- Environment validation must fail with clear error messages
- All security headers must be present in responses
- Missing required variables must prevent app startup
- Development and production configs must be tested

#### Testing Approach
1. Remove required environment variable and verify error
2. Use browser dev tools to verify security headers
3. Test CORS with different origins
4. Verify type-safety of environment variable access
